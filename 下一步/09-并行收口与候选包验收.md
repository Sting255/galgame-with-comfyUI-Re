## 2. 官方跑团：真实模型生成与玩家选择推进

### 2.1 路径、输入与隔离

使用仓库 `runtime/nodejs/node.exe`（Node 22），不启动 `app.js`、完整玩家后端或后台调度器。调用既有 `createGameManager`、游戏 repository、官方 `games/official/trpg-simulator/server/index.mjs` 和正式 LLM 服务。

实际路径：

1. `manager.scan()` 注册官方游戏，`manager.load('trpg-simulator')` 加载真实插件；官方版本 `1.0.0`。
2. 通过真实 Express `Router.handle` 调用 `/catalog` 与 `/start`。模式为玩家调查员（`investigator`），不配置 AI 调查员队友；守秘人为独立合成角色。
3. `/start` 实际请求模型生成一张玩家调查员卡，并在内存库建立存档。
4. 首次 `/turn` 获得真实守秘人叙事与行动建议，逐条调用 `/advance` 完成播放。
5. 原样选择模型建议“凑近冰箱看一眼那张便利贴”，再次 `/turn`，由正式规则引擎处理工具并生成后续叙事；完成播放后用 `/state` 回读核对。

使用官方剧本《千万别让猫碰那个祭坛》（`comedy-cat-altar`）。玩家为 28 岁原创档案研究员“林澄（验收原创）”，守秘人为 32 岁原创桌游主持人“沈墨（验收原创）”；没有使用真实玩家角色或人格参与生成。

隔离边界：

- `.env` 只读解析到进程内存，随后在所有业务模块导入前强制覆盖 `DB_PATH=:memory:`、`LOG_TO_FILE=false`，将 `LINSHE_ENV_PATH` 指向本轮临时根下不存在的文件。
- 原生 SQLite 构造器拒绝一切非 `:memory:` 路径；实际观察到的唯一数据库路径为 `:memory:`。
- 图片、音频、data、ComfyUI input/output 和进程临时目录均指向独立临时根。游戏 manager 的 `communityDir`、`mediaDir` 也显式传入临时目录，不依赖仍指向仓库 data 的默认路径。
- 玩家具名资料只在进程内改成上述合成人设，不调用持久化配置入口；游戏存档只写入内存库。
- `imagesEnabled=false`；未启动 ComfyUI，实际 GPU 访问为 0、图片任务为 0，没有与其他代理争用生图资源。
- 每次模型输出预算仅在本进程设为 4096 tokens，总模型请求保护上限为 8 次；实际为 5 次，没有持久化预算设置。

### 3.3 最终规则改动与只读交叉审查

源码改动限于 `agent-core/src/builtinRules.js` 的 `IMAGE_PROMPT_RULE`：前置目标 500–700、上限 800 **字符**（包含空格、标点和身份标签），精简可选场景／光线／氛围，并在输出前逐个具名人物核对必需事实。

最终措辞要求身份标签及反斜线保真、每人分别保留身体／外观锁、服装状态和所属关系、动作与构图；跨人物相同属性不得当成可删的重复。日历日期保持等值英文或数字形式，时钟时间逐字保留，避免把 `16:40` 只改写为“下午”。

只读交叉审查发现过“日期逐字保留”与“全英文、禁止中文”在中文日期输入时冲突，已改为等值英文／数字日期。原有人数声明、每个角色独立句及位置动作、服装和发型所有权、显式视角等规则未被长度目标删除或降为可选。提示词代理报告相关语法与差异检查通过。

**静态规则保留不等于模型实测保真通过。** 最终 943 字符双人样例已实际复验，不能再把最终核对措辞描述成“尚未复测”，也不能把它记为成功。当前仍只有提示词约束，没有硬性长度保证；本轮未采用字符串硬截断、静默删减事实或额外整轮重生成来制造达标结果。
