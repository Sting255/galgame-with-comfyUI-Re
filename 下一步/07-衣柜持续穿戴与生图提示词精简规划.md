## 1. 问题定义与目标

用户明确：**衣服由规划日程时决定**；某个换装点生效后，后续 `null`/缺字段时段继承该套，直到日程标出下一次换衣。日程 `outfit` 是稀疏的换装点，不是每个活动段重新选衣。

需要区分三层：

- **日程真源**：日程数组中的换装点，由程序时间决定当前活动及当前衣服。
- **衣柜槽位**：角色某个 `scene` 的衣服描述；日程引用衣服，不复制完整描述。
- **单图 prompt 快照**：图片任务组装时会把人物资料改写成英文画面 prompt；旧任务/历史图不保证重新读取当前日程。

目标链路：**计划日程含正确换装点 → 运行时读同一程序日期快照并继承 → 匹配角色衣柜 → 实时图片 prompt 使用该套衣服 → 精简之后仍保留关键衣着特征。**

## 3. 已实施阶段 0–1

### 3.1 改动范围

- 新增 `scheduleRules.js`：抽取日程管理与衣服选择共同使用的纯时间区间/主睡眠-小憩分类/当前活动定位。
- 新增 `scheduleSnapshot.js`：按**程序日期**读取 `daily_schedules`，缺当天快照时从 template 只派生一次，并保留奇遇重新占用、同居睡眠拆分、缓存失效等行为。
- `scheduleManager.getTodayScheduleRaw` 与 `outfitScene.getSceneOutfitForNow` 改为使用同一快照解析，避免日程页按模板派生、服装选择却直接回退默认的分叉。
- `outfitScene` 只向当前活动及其之前寻找换装点，不再环形回到当天最后一段把“未来换装”提前应用；`null` 继续继承前一个合法槽。
- 主睡眠且有睡衣时强制换睡衣；小憩不再强制换睡衣；醒后不跨主睡眠继承睡前 outfit。清醒状态标记到睡衣时正确回到日间默认，修复异常/错误返回类型。
- 日程运行时按 `scene`、行 id、唯一名称兼容旧标记；同名歧义不猜测，走安全默认。
- 默认 `work` 即使没有 `character_outfits` 行仍进入候选并作为安全回退。
- `refreshResidenceDailySleep` 使用程序日期而非真实本地日期，避免程序时间偏移后改错日快照。

## 6. 用户确定的产品规则

1. 日程是穿衣决定源；`outfit` 是换装点，后续 `null` 继承到下一换装点。
2. 普通实时新图按 prompt 组装时刻的当前日程；指定历史/未来活动拍照应使用目标段；单图快照跨时段不漂。
3. 固定头像/立绘/历史原图等非实时资产按其既有 base/explicit/snapshot 模式，不自动随日程切衣。
4. 款式稳定目标是主体、主色、关键结构及穿着状态；姿势、镜头和光线允许变化。
