# 03｜分阶段施工计划

> 原则：每个阶段可以独立提交、独立回归、独立停止。不要将全部阶段合成一个“全栈重构”提交。  
> 估时是熟悉仓库的一名全栈开发者完成开发与针对性验证的量级，不是承诺日期；真实排期取决于真机与模型环境。

## 阶段 0｜冻结事实源与保护现场（0.5～1 天）

### 目标

让后续修复有可比较基线，不碰玩家真实数据。

### 工作

1. 固定 Node 22.18.0；根脚本提供 `check:backend`，使用仓库 runtime 执行测试，避免系统 Node ABI 漂移。
2. 建立干净的测试 worktree/临时目录，所有验证使用 `DB_PATH=:memory:` 或临时文件库。
3. 将本目录台账复制为执行清单，每项指定唯一修改人；冻结新玩法，先修 P0。
4. 保存当前测试、lint、构建、依赖审计结果；真实玩家库只在用户明确提供的测试副本上做迁移验收。
5. 为发布版本指定规则：精确 tag、干净树、同一 VERSION；在方案落地前停止根 release 生成正式包。

### 提交划分

- `工程(运行时): 固定Node版本与内存库测试入口`
- `文档(交接): 建立全栈审计与发布基线`

### 完成判据

任何开发者可用一条命令运行 63 个后端用例，且不接触 `agent-core/data/agent.db`；测试/截图/临时日志不进入 git。

## 阶段 1｜凭据、设备与备份止损（2～4 天 + Android 真机）

对应：P0-01～04、P0-08、P1-15～16。

### 1A. 凭据退出与最小读取权限

- 轮换内置 embedding/rerank、MaiBot 默认 Token；移除源码可逆材料。
- `GET webui-settings` 不返回秘密；配置修改区分本机/远程。
- 默认日志脱敏，TLS 改成 provider 级；TTS 服务 Token 随机化。
- 旧 Android 签名废弃状态确认；公开包不含敏感历史。

### 1B. Android 设备授权

- 先实现独立 device token、撤销与 SSE Bearer，再迁移网页配对；保留现有根配对码作为一次性交换。
- approvedOrigin 限制导航与桥；关闭全局混合内容；明确 LAN HTTP 仅是便利模式。
- 401 停止原生重连；切网/重启/轮换用可观察状态处理。
- TTS/vector/ComfyUI 服务只绑回环，PM2 示例同步修正。

### 1C. 备份秘密与文案

- 立即改 UI/README：数据库本身可能含秘密，不勾 `.env` 不等于无敏感信息。
- 设计 secrets 脱敏导出；若本阶段无法实现，保留“所有备份均敏感”的明确提示，不制造虚假安全选项。
- 资产恢复模式先统一文案，再实现快照/合并；恢复 journal 在后续数据阶段完成。

### 验收

- Android 真机配对、后台 SSE、401、凭证撤销、锁屏、切网。
- 非批准 origin 无桥能力；外站跳系统浏览器。
- 导出包秘密扫描；历史敏感对象扫描；不含签名材料。
- 正常日志与提供给他人的诊断包不含 Key/正文/思维链。

### 提交划分

- `安全(凭据): 移除内置秘密并收紧桥接配置读取`
- `安全(安卓): 贯通设备配对并限制原生桥来源`
- `安全(备份): 明确秘密分类与敏感导出边界`
- `安全(日志): 默认脱敏并隔离TLS配置`

## 阶段 2｜消息与核心生成正确性（2～4 天）

对应：P0-05～06、P1-01～02、P1-18、P1-21。

### 工作

1. 群聊流：保存 abort、首帧/无活动超时、按群 sending、失败乐观消息、离页清理；后端明确轮次取消与重连恢复。
2. App 全局 SSE：所有订阅可退订，消息 ID 去重；独立立绘页往返测试。
3. JSON：续写只在严格完整时成功；repair 只能最终降级，领域必填校验不可省。
4. 身份：本体编辑只写 `identity_anchor` 并 manual；服装读取与所有生图仍走统一入口。
5. 传媒/玩具/触摸：请求 generation 与 entity id 校验，先修响应串对象，再抽共享 composable。

### 自动回归（少量但能独立运行）

- `groupStreamLifecycle.test.js`：首帧、无活动、abort、错误、连续发送。
- `streamSubscription.test.js`：effectScope 退订与重复挂载。
- `jsonContinuation.test.js`：截断/围栏/重写/拒答/修复误判。
- `identityAnchor.test.js`：本体编辑、manual、服装/生图读取。
- `requestOwnership.test.js`：A→B 的乱序响应。

这些是针对当前保留测试缺口的正式可运行回归，不写临时 `debug-*.js`，运行通过后纳入 CI。

### 验收

- 断流后队列不锁；反复立绘页不重复消息。
- 半截 JSON 不公开；合法 JSON 不被误判截断白烧续写。
- 角色本体保存后五类场景身体一致，新旧衣服不污染锚点。
- A→B 请求晚到不覆盖 B。

### 提交划分

- `修复(群聊): 补齐流超时取消与失败恢复`
- `修复(实时事件): 统一订阅退订与消息幂等`
- `修复(LLM): 区分完整续写与修复降级`
- `修复(角色本体): 收敛身份锚点写入真源`
- `修复(前端竞态): 绑定异步响应与业务对象`

## 阶段 3｜持久任务、公开闸门与恢复（5～8 天）

对应：P1-03～14、P0-09；建议拆成 3A～3D 四次交付。

### 3A. 公共任务最小骨架

- 定义状态语义、原子认领、retry/next_attempt_at、启动恢复清单、discard 终态。
- 不新建“大而全”框架，先给评论队列和回复队列使用。
- `moment_comment_queue` 加唯一约束与回复评论 ID；迁移已有 waiting/processing/done 数据前去重。
- 回复队列只认领到期的同组消息；公开前重新检查睡眠。

**验收**：三个崩溃点恢复不丢不重；未到期条目不提前。

### 3B. 媒体与社交公开链

- 媒体 feed 的候选、认领、写回、完成统一排除 discarded。
- 媒体新增“只发布、不生图”的到期扫描，保留既有 GPU 降载决策。
- 朋友圈逐说话人公开前复查；群聊图片走同一睡眠过滤。
- 自动奇遇首幕在事务前按自动入口语义检查；手动入口不误伤。
- 特殊日程 generating 记录所有权并启动回收。

**验收**：在每个 LLM/生图 await 后注入睡眠、开关、删除、系统角色；终态不复活，延期会自动续。

### 3C. 离线与日记

- 离线失败分片 pending/dead-letter；未决不清游标；低频 tick 根据 retry_at 续跑。
- 日记 deferred 状态持久化，确认稿/快照/重试键完整；重启、手动重试与自动重试互斥。
- 信箱已有生成前后闸门与恢复，作为参考，不重复重写。

**验收**：网络失败、单片失败、角色醒来、进程退出后，内容只公开一次且不缺段。

### 3D. 数据迁移、备份代际与外部执行器

- `PRAGMA user_version`、版本化事务迁移、busy_timeout、结构错误阻断。
- restore_generation 强制索引 stale，当前 provider 重建；嵌入不可用时暂停且可观察。
- 恢复 journal 持久化，快照/合并语义实现一致。
- ComfyUI 全生命周期超时、下载上限、取消与 promptId；GPU 队列有界、关闭闸门。
- TTS 纳入托管生命周期，保持 GPU 互斥。

**验收**：旧库升级与回滚、恢复中强杀、空/错 Chroma、ComfyUI 停顿/超大响应/关闭均有确定终态。

### 提交划分

按领域分别提交：`评论队列`、`回复队列`、`媒体状态`、`社交公开闸门`、`离线续跑`、`日记延期`、`数据库迁移`、`备份恢复`、`外部任务生命周期`。不要把 3A～3D 合成“修复后台若干问题”。

## 阶段 4｜发布链、依赖与 CI（3～5 天 + 干净机）

对应：P0-07～10、P1-22、P2-06～09。

### 工作

1. 合并发布脚本共享库：一个正式入口、一个版本来源、一棵干净树、一套敏感检查。
2. 删除 `--normalize-integrity` 无效调用；builder 继续负责 EXE 完整性和自检。
3. 发布源采用净化导出/发布仓库，不复制含旧私钥的开发历史；保留可更新性的替代设计。
4. Node 依赖小步升级，复核生产告警；不执行盲目 `audit fix --force`。
5. Python constraints/hash、模型 revision 与 hash、Gradle lock/verification，记录 SBOM。
6. CI 分 job：Node 测试、前端 lint/build、TTS Python 测试、发布门禁；原生模块必须实际安装/加载。
7. Launcher 与网页数据迁移统一；端口与 PM2 监听修正；README/CHANGELOG 清理旧仓库/旧功能文案。
8. APK 被要求时，构建或 lint 失败必须阻断；签名配置只在受控本地/CI secret 中。

### 验收

- 从干净精确 tag 的临时 worktree 完整构建。
- 解压到含中文、空格、无管理员权限的干净目录，启动 vector 与 agent-core。
- `/api/health` 与 `/api/characters` 正常，前端 hash 与当前构建一致。
- 包内无 `.env`、`launcher_config.json`、签名材料、玩家库、敏感 Git objects。
- CI 绿灯必须包含真实测试，不只是静态扫描。

## 阶段 5｜UI 基座、性能与可维护性（4～7 天，可部分并行）

对应：P1-19～21、P2-01～05。

### 5A. 先修基座

- NavBar 全部 router-link；LinsheSelect 完整键盘交互；LinsheModal aria-labelledby。
- 移动建群、GlobalLora、角色详情、酒馆世界观等迁移基座；保留特殊布局。
- 统一 300ms 过渡和 reduced-motion；关闭 after-leave 后卸载。
- Toast/灯箱/场景 Tabs 键盘操作；裸 input/switch/button 按白名单收口。

### 5B. 再优化数据与拆分

- 朋友圈首屏一页，作者聚合与筛选下推；2000+ 数据验证。
- 按业务域抽 `api/index.js`、settings、chat/group composable；先解决真实重复与竞态。
- 小镇死接口/SSE/旧选项清理以 import 图为依据，通用组件改语义中立命名。
- lint 先未使用/props 所有权，再单独格式化；设置 warning 上限逐步降到 0。

### 验收

桌面 1440×1000、1366×768、1024×768；移动 390×844、320px；200% 缩放；暖色/暗夜；键盘与读屏；reduced-motion。必须覆盖真实长文本、多图、多个角色、嵌套弹窗，不能只用空库。

## 阶段 6｜明确不做或后续再议

1. **反重复重写已流式内容**：当前协议只能追加，不支持替换。若未来要做，先定义可撤回/替换的流协议与消息版本，不在 prompt 里加一个开关就算完成。
2. **多后端实例/公网多用户**：需要设备与用户模型、租约、HTTPS、速率限制和运维体系，超出当前单机目标。
3. **全量历史测试恢复**：历史测试存在不等于可运行。只恢复发布边界和高风险用例，先保证独立可运行。
4. **完整小镇恢复**：当前产品明确剥离。若要恢复，先单独立项，不由残留配置开关隐式承诺。
5. **全站换肤/框架迁移**：当前收益低、回归面大，不进入近期路线。

## 提交与审查规范

### 每个提交必须回答

1. 解决台账哪个编号？
2. 改动前的可复现路径是什么？
3. 数据库/文件/外部服务哪个是真源？
4. 任务在哪个崩溃点会恢复或重试？
5. 是否改变手动与自动入口语义？
6. 跑过哪些命令、哪些真机步骤没跑？
7. 数据迁移、备份与回滚怎么处理？

### 禁止的“完成”描述

- “应该没问题”“理论上不会重复”——没有验证就不能关闭。
- “测试通过”——必须写运行时、数量、跳过项和范围。
- “UI 已适配”——必须写尺寸、主题、数据状态与截图。
- “已延期/已恢复”——必须证明存在后续驱动和幂等。
- “已脱敏”——必须对实际归档/日志做秘密扫描。
- “已发布”——必须有候选包路径、commit、校验和与三步交付验收。
