# Learnings

2026-11-05：用户明确模型设置已足够完善后，停止单独扩改该分区，将当前任务收敛到上下文条移除与私聊／群聊组件 UI。通用“继续优化”不应覆盖用户后来明确的优先级；旧数据仍排除。浏览器挂载真实 store 时要替换自动加载方法，避免模拟接口的空响应清掉已准备的合成夹具。

2026-11-05：多请求设置保存要等整条链成功才清空草稿，API 包装层必须透传业务成功/失败结果；中途失败不等于服务器已回滚。删除非活动配置不重载表单，切换后的刷新只更新该配置拥有的字段，避免覆盖其他分区的本地编辑。

2026-11-05：配置测试也需要与用户文件隔离，不能靠写真实 .env 后还原。复用既有 LINSHE_ENV_PATH，让启动读取、设置保存和备份共用路径；模型桩必须显式提供假凭证，避免依赖开发机 Key。配置序列化应以 dotenv 实际解析结果验证，不能套 JSON/shell 转义规则。

2026-11-04：共享队列释放、回复队列恢复和图片工作流归因必须使用任务自身持有的信息；可变全局状态只能作为新任务的默认选择。

## 2026-11-04 · 用户明确程序与玩家数据的边界

- 用户要求只修程序和优化架构，旧存档、立绘、历史素材不在本任务范围。日常审查不扫描或复制玩家数据，不把旧缺图列为程序缺陷。
- 使用内存库、合成临时库与模拟素材验收；迁移兼容性用版本夹具验证。已更新执行约定和项目现状，避免后续接手重复偏离范围。

2026-11-05：用户指出将动作、玩具、推进入口统一堆到输入框上方会与对话推测冲突。布局验收必须同时挂载推测、输入框和工具，覆盖私聊／群聊窄屏；还要实际展开面板内部的分类、页签与折叠内容，不能只验入口。前端全量通过不代表桌面 EXE 能启动。

2026-11-05：列表轮询会替换对象，详情应保存 ID 并从当前 store 派生；异步列表返回还需同时校验请求顺序和本地更新版本，避免重投被还原、已删除信件复活。失败展示要检查完整 v-if 顺序，不能只确认源码里存在 failed 分支。页面与弹窗两个入口应共用重投／删除逻辑，并实际覆盖窄屏和寄送中的取消操作。

2026-11-05 用户纠正：聊天输入区的动作／玩具／亲密入口应保留原有圆形配图按钮，不改成展开文字的胶囊。抽公共组件只整理代码和状态，不顺带替换用户认可的视觉形式；桌面与手机保持图标，名称走 title 与 aria-label。
