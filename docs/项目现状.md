## 项目与运行

邻舍.EXE 是 AI 角色陪伴应用：私聊、群聊、记忆、朋友圈、信箱、日程、事件、生图与语音。当前 VERSION 为 4.1.1，基于上游 icecranberry/galgame-with-comfyUI 的个人 fork；下载仓库为 Sting255/galgame-with-comfyUI-Re。

五个程序分别在 agent-core（Express/SQLite）、web-ui（Vue/Pinia）、launcher（桌面启动器）、tts-service（本地语音）、vector-service（向量检索）。Android 壳在 android-shell。运行时、用户数据、分发包不属于待整理源码。

本机后端 PORT=3199，默认配置仍为 3099；以启动日志和 /api/health 的 application、pid、port 为准。启动、测试、构建命令见 [项目结构](operations/project-structure.md)；联调路径见 [验收环境](验收环境-凭据与路径.md)。

## 仍需处理

1. **核心大文件**：SettingsView.vue 约 4,900 行、db/index.js 约 4,100 行、ChatView.vue 约 3,600 行、routes/chat.js 约 3,400 行、api/index.js 约 2,800 行。当前拆了服务器生命周期、备份辅助模块与设置页备份、设备、模型配置列表，尚未重构整条聊天链。当前先收口聊天组件，再按具体缺陷处理聊天上下文和持久化边界；模型设置暂不继续拆分。
2. **数据库迁移**：仍使用启动时幂等迁移，未引入版本机制。版本化前要覆盖历史库升级与失败恢复。
3. **小镇遗留与模块依赖环**：世界页已删除，但聊天、事件、朋友圈仍复用部分能力。不可按 town 文件名整目录删除；先确认生产入口可达性。
4. **备份的运行时边界**：数据库快照一致，文件资产尚无跨任务快照；大量生图或录音写入时应先停任务再导出。恢复期间 DB 写入被阻止，但外部生成任务不是全部可取消。
5. **代码规范积压**：前端已有数百条 lint warning，需按改动模块逐步收敛。配对保护默认服务于本机与可信局域网，公网与反代须按设备访问文档配置。
6. **设置存储边界**：模型配置仍分布在 .env 与 system_settings。已保证配置文件写入失败时不提前修改运行状态或活动档案，并保留前端未完成保存的草稿；文件与数据库以及多次设置请求尚无统一事务，后续需要收口为完整的模型设置保存入口。

程序时间与后台真实时间排期有意分离：推进游戏一天不等于让朋友圈、信箱和事件后台立即跑完一天。这是当前设计边界。
