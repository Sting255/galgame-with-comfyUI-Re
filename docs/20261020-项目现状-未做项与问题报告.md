## 二、逻辑问题（会直接让用户看到错误表现）

### L1. 服装面板失败时永久「加载中…」（用户实际踩到）

`CharacterDetailModal.vue:733-759`：

```js
try { ... } catch (err) { console.error(...); detail.sceneOutfits = [] }
```

模板 `v-else class="scene-edit-empty">加载中…`（:163）在 `sceneOutfits` 为空时**永久显示**，没有错误态、没有重试、没有空态文案。
接口 `GET /api/characters/:id/outfit-scenes` 一旦 404/500/超时（换机器、旧包、后端未起），用户看到的就是「默认 · 私服 · 居家 · 睡衣 + 加载中…」四行，永远不动。

### L2. 破限词无差别注入给「小任务」

`promptShield` 按**功能域**（chat/group/event/...）投递，粒度太粗。日志实证：一轮聊天里注入 5~6 次，每次都是同一份 2452 字：

| 调用点 | 每轮次数 | 是否真需要破限词 |
|---|---|---|
| 主聊天流 | 1 | 需要 |
| 预测（`max_tokens:128`） | 1 | **不需要** |
| 情绪判断 | 1 | **不需要** |
| AI判断行为 | 1 | **不需要** |
| 判断需要图片（`max_tokens:5`） | 1 | **不需要** |
| 生图 prompt | 0~1 | 部分需要 |

`max_tokens:5` 的判定任务也背 2452 字 system，纯浪费首字延迟与 token。

### L3. 「一次吐一堆」= 多路产物在同一时刻才 flush

聊天流结束后才并行触发 `guessPromise` / `imageGenPromise` / `judgeImageNeed`（`chat.js:1979/2125`），并且 `mergeMessages=true`。用户观感：长时间无输出 → 突然一条长消息 + 图 + 建议一起出现。

### L4. 生图排队有 60s 硬上限，且会「跳过静默期」抢跑

日志 6 次：`低优生图已等 60s（上限 60s），跳过静默期直接派发，避免后台玩法被饿死；队列还剩 N 张`。说明当轮生图需求 > 产能（单 ComfyUI 队列），聊天里的图会被后台（朋友圈/报纸）挤到 60s 后。

### L5. RAG 重排对长查询直接失败

日志 1 次：`reranker: 系统内置重排服务失败 (1/1): Query is too long`。群聊记录拼进 query 后超模型上限，降级到无重排（hits=12 质量下降）。没有截断。

### L6. `ComfyUI /object_info` 不可用时只重试不降级

日志 4 次 `object_info unavailable (fetch failed), retrying in Ns`。若 ComfyUI 掉线，生图链路会长时间卡在重试，而聊天侧没有「图先不生成」的快速失败路径。

## 三、代码问题（不立即报错，但会持续消耗/埋雷）

### C1. 破限词正文与「任务格式要求」耦合在同一段里

`DEFAULT_PROMPT` 里既写行为约束又写 JSON 合同说明，长度 2452 字。任何一次改口径都要全量重写，且对所有调用点同时生效。

### C2. 服装生成入口只有「按默认生成其余三套」一个按钮，且被 `v-if="detail.sceneOutfits.length > 1"` 包住

后端已有 `POST /:id/outfit-scenes/generate`（支持 `save`），但没有「一次点完四套 + 落库 + 失败重试」的前端编排；用户描述「现在还得一个个点」与此吻合：批量按钮在异常路径（接口失败/空数组）根本不渲染。

### C3. `sceneOutfits` 用索引当 tab value

`sceneTabOptions` 用 `value: index`，`activeSceneOutfit = sceneOutfits[sceneTab]`。数组长度变化（重新加载/失败清空）后 tab 索引会指向错误项或落空——这是 L1 的放大器。

### C4. 无注入幂等之外的「按 label 跳过」能力

`promptShield` 只认域，不认 `label`；要瘦身必须先加 label 维度（本次要做）。

### C5. 34 处 TODO/FIXME/「暂时隐藏」

其中 `contextAssembler.js` 占 4 处；`CharacterDetailModal` 的「外观/体型」入口有「暂时隐藏」注释（`outfitService` 的详情卡入口）。这些是可见功能缺口，不是死代码。

### C6. 前端 3 个上游测试仍 `skip`

`chatImageRagQuery.test.js:152`、`llmOutputTokens.test.js:33/34`、`toyWakeAndImage.test.js:84`——对应实现未合，属于已知债务（不是本轮引入）。
