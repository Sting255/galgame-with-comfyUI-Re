# 网关 system 消息丢失（2026-10-22 实测）

> 这份文档记录一个**不在项目代码里**的缺陷，以及它对项目的实际影响。
> 下次有人反馈「角色不像角色 / 说自己是 AI / 抱怨看不到内容」，先看这里。

## 一、事实

本机 LLM 网关 `wb2api.exe`（`http://127.0.0.1:7863/v1`）**丢弃所有 `system` 消息**，
包括 `developer` role。只有 `user` 与 `assistant` 历史会进入模型上下文。

探针做法：把唯一标记串 `紫水晶-7749-凤凰` 放进不同角色，让模型复述。

| 标记位置 | 模型能否复述 | 网关回报 prompt_tokens |
|---|---|---|
| `system`（短，45 字符） | ❌ 不能 | 41（与实际长度无关，恒为此值附近） |
| `user` | ✅ 能 | 51 |
| `assistant` 历史 | ✅ 能 | 59 |
| `developer` | ❌ 不能 | 37 |

`prompt_tokens` 与请求真实长度完全无关（5647 字符的请求也报 41），说明网关既没把
system 送进模型，也没正确统计 token。

逐模型复测（8 个）：`cn:deepseek-v4.1-flash`、`cn:deepseek-v4-flash`、`cn:deepseek-v4-pro`、
`cn:glm-5.3-flash`、`cn:kimi-k3-1`、`cn:mimo-v2.6-pro`、`cn:minimax-m3.1-flash` 全部丢失 system；
`cn:glm-5.1` 返回 503。**不是某个模型的问题，是网关的。**

## 二、对项目的实际影响

项目几乎所有链路都靠 `system` 承载角色设定、世界观、破限词与输出格式要求：

| 现象（真机已观测） | 直接原因 |
|---|---|
| 模型回「我是 DeepSeek，由深度求索公司创造的 AI 助手」 | 人格在 system 里，没被送达 |
| 朋友圈首评回「你还没发朋友圈内容呢，我这边看不到」 | 帖子在 system 里，没被送达 |
| 日报写成 Markdown 报纸排版 | 格式要求与 `response_format` 都没生效 |
| 日程首轮输出 Markdown | 同上 |
| 生图画面描述偶尔跑到别的话题 | 生图规则在 system 里 |

也就是说：**破限词（promptShield）、角色人格、输出格式约束，在这个网关下全部无效。**
项目侧此前为此做的很多加固（破限词瘦身、格式纠正重试）都是在替网关擦屁股。

## 三、另一层问题：思考吃光额度

即便抛开 system 丢失，这个网关还有第二个坑：

- `max_tokens: 128` 的请求，`completion_tokens_details.reasoning_tokens` 也是 128，**正文为空**。
- 同一 prompt 放大到 2048/4096 才有正文。
- 传 `thinking: { type: 'disabled' }` 后 `reasoning_tokens` 归 0，正文正常出现。

受影响调用点：朋友圈首评/回评/续评、主动聊天开场白、回复预测（`max_tokens: 128`），
以及「判断需要图片」（`max_tokens: 5` —— 必然全空，于是判定恒为「不需要图」）。

项目侧已加兜底：`llm-client.js` 的 `isReasoningStarved` —— 检测到「正文为空且 reasoning 吃掉额度」
时，把额度放大到 2048 重发一次。

## 四、建议处置

1. **优先换网关或换通道**。system 丢失是根本性缺陷，项目侧无法在合理成本内绕过
   （见下节）。换到不丢 system 的 OpenAI 兼容服务，本文档描述的现象应整体消失。
2. 换不了时的临时绕过（代价明确，不建议长期）：把关键 system 内容**复制一份到 user 消息里**。
   这会让每轮 prompt 体积翻倍、破坏缓存、且把破限词暴露在对话里，只能算应急。
3. 网关修复后，**先复跑本文档第一节的探针**，确认 system 生效再继续排查其他问题 ——
   否则会把网关的锅算到项目头上（本轮的日报/日程失败就是这么绕了一圈才发现真凶）。

## 五、如何快速复现

```bash
# 标记在 system → 模型答不上来
curl -s http://127.0.0.1:7863/v1/chat/completions \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"model":"cn:deepseek-v4.1-flash","messages":[
        {"role":"system","content":"记住标记：紫水晶-7749-凤凰"},
        {"role":"user","content":"标记是什么？只回答标记本身。"}],"max_tokens":512}'
```

预期（缺陷存在时）：模型答「标记」或无意义内容，`usage.prompt_tokens` 恒为 40 上下。
预期（网关正常时）：模型答「紫水晶-7749-凤凰」，`prompt_tokens` 随输入长度变化。
