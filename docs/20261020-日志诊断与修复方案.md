### 关键推论：慢不在「模型」，在「每轮干的事太多 + 每件事都背同一份长 system」

一轮聊天真实触发 **5~6 次 LLM 调用**：

```
主聊天流(1) + 预测(1) + 情绪判断(1) + AI判断行为(1) + 判断需要图片(1) [+ 生图 prompt(0~1)]
```

而每一次（包括 `max_tokens:5` 的「判断需要图片」）都被 `promptShield` 插入 **2452 字** 破限词。
所以用户感受到的「点一下要反应一会」「突然吐一堆词和图」= 多路调用串起来 + 结果在同一时刻 flush。

## 二、逐条诊断与处置

### D1. 破限词太长（用户判断正确，但根因是「注入范围」不是「长度」）

**证据**：223 次注入，每次 2452 字，`来源=default`；注入点包括 `预测`、`情绪判断`、`AI判断行为`、`判断需要图片`、`对话摘要提取助手`。

**判断**：把这 2452 字砍到 600 字只省 30%；把它从 4 个短任务上摘掉能省 80% 的无效开销。

**方案（分两层）**：

1. **按 label 白名单注入**（主力修复）：`promptShield` 增加 `SHIELD_SKIP_LABELS`，短分类任务一律跳过——
   `预测`、`情绪判断`、`AI判断行为`、`判断需要图片`、`对话摘要提取助手`、`约定检测判断`、`标题生成`、`AI标题`。
   这些任务输出 5~128 token，且不写正文，天然不会被拒答。
2. **默认换短版**：新增内置规则集「紧凑版（~600 字）」作为默认，保留现 2452 字版为可选。
3. **上游作者的词**：作为第 4 个内置规则集挂进来（用户要求「默认就用上游作者的词」）。
   获取路径：`icecranberry/galgame-with-comfyUI` 仓库内的破限/system 提示词文件 → 原文入库为 `builtin: upstream-author`，默认启用。
   若上游词拿不到（网络/文件定位失败），先落「紧凑版」并在设置页留一键切换。

### D2. 玩具 / 推进「点一下反应一会」

**证据链**：`intimate-action` 20 次（avg prompt 4.2k）、`AI判断行为` 每轮 1 次（max_tokens 500、prompt ~4k）、同轮还要走 `judgeImageNeed` → `生图`。

**方案**：

1. `AI判断行为` 改为**不阻塞**：动作先返回、判定结果用作下一轮上下文（现状是 await 后再动作）。
2. `judgeImageNeed`（max_tokens:5，纯分类）与主聊天流**并行**发起，而不是等流结束再判断。
3. 前端「推进」按钮加即时反馈（按下即显示 typing 态），避免用户以为没响应。

### D3. 「长时间不说话 → 突然吐一堆词和图」

**证据**：`chat.js:1979/2125` 在流结束后才触发 `generateReplyGuesses` / `handleNeedImageFlow`；`mergeMessages=true`。

**方案**：

1. 主聊天流**首 token** 就推 SSE（现在疑似被缓冲）；检查 `consumeStream` 是否在等完整回复再 flush。
2. `mergeMessages` 改为「短消息合并、长消息不合并」，避免一次性 4~5 段齐发。
3. 图片走「先占位后补图」：SSE 先发 `image_pending` 卡片，图好了再替换 —— 用户不会再觉得「卡住」。

### D4. 生图被后台挤占（60s 上限 6 次）

**方案**：队列优先级从「低优等待静默期」改为**会话级优先**：当前打开会话的聊天图最高优，朋友圈/报纸降级；60s 上限保留，但后台任务不得让前台等待超过 10s。

### D5. 服装面板永久「加载中」（用户实际踩到，另一台电脑）

**证据**：`CharacterDetailModal.vue` 接口异常 → `sceneOutfits=[]` → `activeSceneOutfit=null` → 板模板固定输出「加载中…」；无错误态、无重试。

**方案**：

1. 三态化：`loading / error / empty`，`error` 显示「外观加载失败 · 重试」按钮 + 具体原因（HTTP 状态）。
2. `sceneTab` 从「数组索引」改为「场景 key（work/home/private/sleep）」，数组变化不再错位。
3. 容错：接口 404 时前端回落到「本地默认四套骨架」，至少让用户能编辑文案。

### D6. 一键生成「一个系列的服装」（用户明确要）

**现状**：只有 `按默认生成其余三套`（`v-if="detail.sceneOutfits.length > 1"`），异常路径不渲染；一次只能生成一套或依赖批量接口。

**方案**：

1. 后端 `POST /:id/outfit-scenes/generate` 增加 `mode: 'series'`：一次生成 4 套（默认为锚，其余只换衣服），**逐套落库、逐套 SSE 进度**，失败可单套重试。
2. 前端加「一键生成整套系列」主按钮（不受 `length > 1` 限制），带进度条与逐套状态（生成中/成功/失败+重试）。
3. 复用现有 `sceneOutfitBatch`（已有批量骨架），补 `series` 编排与幂等（同角色重复点击不重复扣费）。

## 四、验收口径

- 服装面板：断开后端/接口 500 时，显示「加载失败 · 重试」，点击可恢复；正常时 4 套 ≤ 1.5s 渲染完成。
- 一键整套：单角色 4 套一次生成，逐套落库；重复点击幂等（不重复扣费）；失败套可单独重试。
- 破限词：日志中 `预测 / 情绪判断 / AI判断行为 / 判断需要图片` 不再出现 `注入破限提示词`；主聊天流仍注入。
- 聊延迟：同一轮从「发送」到「首字」目标 ≤ 1.5s（本机网关），`AI判断行为` 不再位于首字前。
- 生图：前台聊天图不再出现「已等 60s（上限 60s）」告警。
- 测试：后端 2228 / 前端 925 保持全绿（新增测试单独计数）。
